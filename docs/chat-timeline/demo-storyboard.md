# Real-app demo plan

Target: about 20 seconds, square 1080×1080 or higher, clear iPhone framing, minimal text. Capture the accepted feature build on iPhone 15/iOS 26. Keep the original recording.

| Time | Action | What the viewer learns |
|---|---|---|
| 0–3 s | Read a visible message in a long public channel; open Timeline | The feature belongs to the actual chat |
| 3–8 s | Select an earlier year/month/day with the scrubber | Fast, deliberate navigation across dates |
| 8–11 s | Pause on the real message preview and its actual date | Inspect the destination before leaving the current place |
| 11–15 s | Confirm Jump; show the highlighted destination | The preview opens the corresponding message |
| 15–19 s | Use Return | The original reading position is preserved |
| 19–21 s | Brief stable final view | The result is clear without an explanatory slide |

Use an accessible public channel containing the selected dates. Pick dates from actual test results, not invented example content. Avoid personal chats, phone numbers, authentication screens, or unapproved messages in the capture.

Compose framing and intentional camera crops around the genuine recording. Do not redraw the preview, date slider, or navigation in post-production. Editing may remove idle setup, but must not hide functional failures or turn a non-working prototype into an apparent working feature.

Record a separate uncut verification take that includes cancel, return after a new message, theme changes, and slow/error states. The short promotional cut is not the full acceptance evidence.
